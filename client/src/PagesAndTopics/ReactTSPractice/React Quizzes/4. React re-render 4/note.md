# React: Рендер и re-render через children
## (по мотивам задачи BFE.dev)

---

## 1. Консольный вывод

```
"App"
"A"
"B"
"C"
"D"
"A"
```

---

## 2. Пошаговый разбор рендера

### Первый рендер (mount)
1. Вызывается компонент App:
   - Лог: "App"
2. Внутри App рендерятся:
   - <A><B/></A>
   - <D/>
3. Рендер компонента A:
   - Лог: "A"
   - Возвращает children — это <B/>
4. Рендер компонента B (children для A):
   - Лог: "B"
   - Возвращает <C/>
5. Рендер компонента C (children для B):
   - Лог: "C"
   - Возвращает null
6. Рендер компонента D (из App):
   - Лог: "D"
   - Возвращает null

### useEffect в A (после маунта)
7. useEffect в A срабатывает один раз после маунта:
   - setState вызывает повторный рендер A
8. Повторный рендер A:
   - Лог: "A"
   - Возвращает тот же children (React-элемент <B/>)
   - B и C не рендерятся повторно, так как ссылка на элемент не изменилась

---

## 3. Ключевые нюансы

- children в React — это React-элемент, а не функция. Если родитель возвращает тот же элемент, React не вызывает повторно его рендер.
- Если бы A внутри себя создавал <B/>, то при каждом рендере A вызывался бы и B.
- D не зависит от состояния A, поэтому рендерится только один раз.

---

## 4. Практические выводы

- Чтобы избежать лишних рендеров дочерних компонентов, передавайте их как children сверху, а не создавайте внутри родителя.
- Это позволяет оптимизировать производительность React-приложений.
