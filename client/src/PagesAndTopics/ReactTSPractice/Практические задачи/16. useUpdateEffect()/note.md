Отличный вопрос!  
Это предупреждения от линтера eslint-plugin-react-hooks, который помогает писать безопасные хуки в React.

### 1. "React Hook useEffect was passed a dependency list that is not an array literal."
**Что это значит:**  
Ты передаёшь в useEffect не массив, а переменную (deps?: DependencyList).  
Пример:
```ts
useEffect(() => { ... }, deps)
```
Линтер не может проверить содержимое deps на этапе компиляции, потому что не видит, что именно ты туда передаёшь.  
**Рекомендация линтера:**  
Передавать всегда массив литералом, например `[a, b]`, чтобы он мог проверить зависимости.

### 2. "React Hook useEffect has a missing dependency: 'effect'."
**Что это значит:**  
Ты используешь переменную effect внутри useEffect, но не указал её в массиве зависимостей.  
Пример:
```ts
useEffect(() => { effect(); }, deps)
```
Если effect — это функция, определённая вне компонента или изменяющаяся между рендерами, useEffect может работать некорректно, если не добавить effect в зависимости.

**Рекомендация линтера:**  
Добавить effect в массив зависимостей:
```ts
useEffect(() => { ... }, [...(deps || []), effect])
```
или, если effect не должен меняться — обернуть его в useCallback в родительском компоненте.

---

### Как быть в кастомном хуке?
- В кастомных хуках часто передают deps как параметр, чтобы хук был универсальным.
- Линтер не может проверить deps, если это не литерал.
- Для production-кода и библиотек это нормально, но для проектов с жёсткими линтерами можно:
  - Добавить комментарий-исключение для линтера (`// eslint-disable-next-line react-hooks/exhaustive-deps`)
  - Или явно расширить deps: `useEffect(..., [...(deps || []), effect])`

В твоём случае — это ожидаемое поведение для кастомного хука, и его можно игнорировать или отключить для этой строки.
